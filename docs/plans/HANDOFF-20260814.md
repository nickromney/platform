## Guards added, so these do not need watching

Every failure this session was a *silent success*, not a loud failure: a green
suite hiding an empty fixture, a `Synced` Application on a broken allowlist, a
missing alias surfacing hours later as unexplained pull failures. Watching is
bad at that; assertions are good at it. Each guard below is tied to a specific
incident and was verified by reproducing that incident.

**`make test-ci` now asserts it changed nothing.**
`scripts/check-worktree-unchanged.sh` snapshots `git status` before the suite
and compares after. Proven by reintroducing the `cp` bug: bats exited 0, the
guard exited 1 and named `cp`. A dirty tree at snapshot time is fine, so this
works mid-session.

**`make -C kubernetes/kind check-policy-drift`** compares live
CiliumClusterwideNetworkPolicies against the rendered source, and runs inside
`check-health`. Before the apply it reported 1 of 32 drifted and named the missing
`dl.gitea.com`, while the `gitea` Application read `Synced/Healthy` off a warm
cache. That contrast is the whole point: the Application row was wrong and the
assert was right. It now reports all 32 matching.

**The version audit can fail instead of reporting.**
`--strict` makes an unverifiable dependency exit non-zero rather than print an
ordinary row; wired into the version-audit workflow with
`--allow-lookup-failures`, so a transient upstream lookup is tolerated but a
missing lockfile entry never is. It passes today only because the yarn.lock fix
landed.

**The host alias repairs itself.**
`make -C kubernetes/kind install-host-alias-timer` installs a user systemd
timer (no sudo; you are in the `docker` group) firing 30s after boot and every
5 minutes. Installed and verified live: the alias was deleted from a node and
the timer restored it unattended, with the repair recorded in the journal.
`--uninstall` removes it. No-ops on macOS, which has no systemd and does not
need it.

**macOS now has CI.** A `macos-latest` job runs `make test-host-portable`, the
no-cluster/no-Docker/no-network subset, because stock macOS ships Bash 3.2 and
BSD awk rather than Bash 5 and gawk. The new yarn.lock parser was also checked
under `awk --posix` and `awk --traditional` locally.

One caveat worth knowing: `check-bash32-compat.sh` scans only *tracked* files,
so a new script escapes it until `git add`. The three new scripts were scanned
explicitly and are clean.

## Next steps

Nothing is blocked. Sections 1-11 are all closed, decided, or implemented; the
plan document records each one inline. Sections 13 and 14 were closed on
2026-08-14. Section 12 is still open, and is the only item here that needs a
person rather than a change.

**1. Section 12 needs a decision, not an implementation.** Still open. `make -n`
is not a dry run on `plan` or `apply`: the recipe is a single continued block
containing `$(MAKE)`, which GNU make exempts from `-n`, so a "preview" performs
the real operation. This was found by doing it accidentally, mid-session, which
also failed a concurrent operator apply on the state lock. Three options are
written up in section 12; the smallest is an explicit `preview` target plus a
refusal on `--just-print`, the most correct is moving the terragrunt call behind
its own sub-target.

**2. Section 13 is closed.** The two surviving failures were one root cause, and
it was never in the tests. `mk/common.mk` said `SHELL ?= /bin/bash`, which never
fires — GNU make always has a `SHELL` defined, so `?=` is a no-op and recipes
ran under `/bin/sh`. That is Bash on Arch and dash on Ubuntu, and dash aborts on
`set -o pipefail`, so `check-platform-env-file` died on its first line and the
message the tests were asserting never got printed. `SHELL := /bin/bash` fixes
it; two guards in `tests/makefile.bats` stop the shape returning. Settled by
pushing diagnostics and reading the runner's own output, exactly as the section
said it would have to be.

A separate pair had gone red on `main` in the meantime: Dependabot's
`actions/checkout` v7.0.1 bump (#193) missed the `macos-latest` job that
PR #196 added, and the SHAs restated in three workflow tests. Also fixed here.

**3. `MAKEFLAGS += --no-print-directory` is done**, in
`kubernetes/kind/Makefile` only. The root Makefile does not need it: every
`$(MAKE)` in it already passes the flag explicitly. The six per-call-site
workarounds in the test files are left alone — now redundant rather than wrong,
and retiring them is a separate change. See section 14.

**4. One gap left open by section 13.** `tests/release-workflow.bats` was red
and nothing noticed, because it is not in `CI_BATS_TESTS`. It is fixed, but that
list is hand-maintained, so any new test file sits outside the gate until
someone remembers to add it. Adding this one file is a one-line change; closing
the class needs an assertion that every `tests/*.bats` file is either listed or
explicitly excluded. Neither is done.

**5. macOS.** The `host-portable-bats-macos` CI job now covers the no-cluster
subset, but nothing has run the stack end to end on the Mac Mini. Expect the
per-host setup that does not come from git to bite first: `docker login dhi.io`
(required from stage 600), `mkcert -install`, and `make init-env`.

**6. n-dotfiles.** The locale changes there are a separate repository and a
