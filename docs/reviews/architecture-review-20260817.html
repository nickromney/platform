CORRECTION — this recommendation was wrong as originally written. Folding these into the adjacent for_each would have silently dropped break-glass admin access. That resource renders extraArgs as a YAML map (allowed-group: ${…}, sso.tf:1427), and a map key holds one value — but each of these four grants two groups: the app group and local.sso_admin_group. WITHDRAWN — the premise is wrong. Do not do this.

Investigated 2026-08-17. These are not two definitions of the same thing; they are two different chart-sourcing architectures, and collapsing them would break offline operation.

pathsourcerevision
.tf heredocpolicies_repo_url_cluster + apps/vendor/charts/…main
argocd-apps YAMLghcr.io · charts.jetstack.io · argoproj.github.iopinned (v1.21.1, 2.41.0, …)

The .tf path consumes charts vendored into the in-cluster Gitea by sync-gitea-policies.sh — which is what makes the airplane preset work, and what #182 hardened with reset-surviving vendoring retries. The YAML path pulls from upstream at sync time. All 30 apps present in both differ, by design.

What IS real drift, and is worth a separate look

Sync-wave disagreements between the two paths, which are ordering bugs rather than architecture:

argo-rolloutstf 86yaml 87
cert-manager-configtf 5yaml 10
nginx-gateway-fabrictf −4yaml −10
platform-gateway-routestf 20yaml 50

platform-gateway-routes also points at different paths (${var.platform_gateway_routes_path} vs apps/platform-gateway-routes-sso). Deciding which wave is correct changes deployment ordering on a live cluster, so it was not guessed at here.

Lesson, shared with candidate 4: both recommendations mistook a deliberate architectural difference for copy-paste. Two things that look alike at the text level can be load-bearing in different modes — air-gapped vs upstream, list-form vs map-form extraArgs. Measure what differs before proposing a merge.

Top recommendation

Candidate 1 — make the gate enumerate.

Not because it is the biggest — candidates 3 and 5 are far larger — but because it is the one that changes how every other finding gets caught. PRs #195–#202 were disciplined ratchet work, and each one left a guard behind. But every guard is a point guard: assert this file is listed, assert this target is wired. That is negative leverage — each new invariant costs a new test, and each guard is written only after its own defect escapes.

The four invisible test files prove the pattern: the guard against silent shrinkage shipped with the same blind spot, one level up, that it was written to close. Total enumeration minus a named exclusion list converts an open-ended class of misses into a visible, shrinking list. Then apply the identical shape to the linter targets (candidate 6) and to the serial-containment list.

Cheapest real win if you want code deleted instead: candidate 4 — 456 lines, no new concept, pattern already proven one line below.
