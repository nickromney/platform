# Prerequisites

The platform expects a local operator toolchain. The exact checks live in the
repo Makefiles, so use this page as orientation and the `prereqs` targets as
the source of truth.

## Default Kind Toolchain

Let the repo tell you what is missing rather than copying a list:

```bash
make -C kubernetes/kind prereqs
mkcert -install
```

`prereqs` prints an install command per missing tool, tailored to the managers
present on the host. It prefers `mise` (same versions on macOS and Linux) and
emits the version pinned in `.devcontainer/toolchain-versions.sh`, so a fresh
host lands on the toolchain the repo was validated against instead of
resolving `latest`. Hints use `mise use`, not `mise use -g`: pins land in
`./mise.toml` in the repo and your global tool config is left alone.

Preference order is mise, Homebrew, pacman, apt, arkade, curl — self-updating
managers first, arkade only for what they do not carry. Override with
`INSTALL_TOOL_HINTS_MANAGERS`.

The Homebrew equivalent, if you prefer it on macOS or Ubuntu:

```bash
brew install jq kind kubernetes-cli make opentofu terragrunt
brew install bun node
brew install cilium-cli helm hubble kubectx kubie kyverno mkcert yamllint yq
mkcert -install
```

Docker must be reachable before you plan, apply, or reset the Kind stack.

- macOS: start Docker Desktop.
- Linux: Docker Engine is enough. On systemd distros, prefer socket activation
  (`sudo systemctl enable --now docker.socket`) so the daemon starts on demand
  rather than idling at boot. `prereqs` reports which of the two you have.

## Check the Target

```bash
cd ~/Developer/personal/platform
make -C kubernetes/kind prereqs
make -C kubernetes/lima prereqs
make -C kubernetes/lima prereqs
```

Use only the target you plan to run. Lima include VM-specific
requirements that do not apply to the Kind path.

## Kubeconfig Model

The repo prefers split kubeconfigs, for example
`~/.kube/kind-kind-local.yaml`, rather than automatically merging everything
into `~/.kube/config`. `kubie` is the ergonomic way to switch between them.

<Callout type="warning">
  Only use merge targets when you intentionally want a platform context copied
  into your default kubeconfig. The split model prevents accidental cross-stack
  commands.
</Callout>
