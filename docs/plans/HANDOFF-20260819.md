# Handoff, 2026-08-19

Adversarial review of PR #206 on branch `chore/20260818-cmd-review`, and the
fixes that review produced.

Supersedes the root `HANDOFF.md` written by the implementing agents, which is
deleted in this commit. Every claim in it was verified before deletion; two of
its framings were wrong and are corrected below.

## State

`make test-ci` is 1130/1130 (exit 0), `make lint` is clean, and all three
Go modules build and test clean — including under `-race`, which the gate does
not run.

When this review started, CI on #206 was **red**: `lint-and-hermetic-bats`
failed with four test failures, while the branch's `HANDOFF.md` presented every
slice as "Done & verified" and the PR's own test plan had all six boxes
unticked. The gap was not design, it was verification: each slice had been
checked locally with `bash -n`, `shellcheck`, and the one bats file next to the
change. Nobody ran the whole gate, which is exactly what catches the
cross-cutting breakage extraction causes.

## What the review found

### Four regressions, now fixed

Three shared one root cause: **the `local-exec` heredoc extraction moved code
out of `.tf` files, and grep-contract tests still asserted it was there.** The
implementing agents hit this once and fixed it for
`kubernetes/kind/tests/gitops-refresh.bats`; two more files had the same
problem and were missed.

| Test | Asserted | Now lives in |
| --- | --- | --- |
| `kind/tests/platform-gateway-tls.bats:402` | `deadline=$((SECONDS + 180))` in `gateway-bootstrap.tf` | `scripts/wait-for-gateway-crds.sh`, parameterised as `CRD_WAIT_SECONDS` |
| `kind/tests/sso-oidc-health.bats:54,80` | the post-OIDC retry body in `sso.tf` | `scripts/check-cluster-health-after-oidc.sh` |

The fourth was independent: the new tests added to `tests/variant-contracts.bats`
used bare `python3`, which `tests/python-wrapper-policy.bats` forbids. Now
`uv run --isolated python`, matching `ci-workflow.bats` and
`review-environments.bats`.

Each repointed assertion now pins the *intent* rather than a literal that
parameterisation will delete — the failure mode `gitops-refresh.bats` already
documents in its own comments. Where the old test asserted the absence of
Terraform `$$` escaping, that intent is kept as a single `! grep -Fq '$$'`
against the plain script, where a surviving `$$` would mean a botched
extraction. Both `.tf` files also gained a test asserting they delegate to the
script and retain no heredoc.

### A pre-existing bug the extraction surfaced

`tools/platform-workflow-core/run.go` drained stdout and stderr from two
goroutines into one unsynchronised `bytes.Buffer`, and called the caller's
handler from both. `go test -race` reports a data race on
`bytes.Buffer.WriteString`.

**This was losing output.** With the mutex removed, the guard test sees 783–798
of 800 lines — the terminal TUI and the browser workflow UI have both been
silently dropping 0.5–2% of streamed lines, which on an `apply` means terraform
output vanishing from the operator's screen.

The code is inherited verbatim from the TUI on `main`, so #206 did not
introduce it — but extracting it into a shared module doubled its blast radius,
and the extraction was the moment to fix it. Fixed with a mutex around the
shared write.

The gate runs `go test ./...` with no `-race` anywhere, so a race-detector test
would guard nothing. `run_test.go` asserts the observable consequence instead:
every line arrives exactly once, on both streams. Verified to fail without the
mutex.

### Drift the refactor left open

`tools/platform-workflow-ui` parsed `options.json` into a `UIRules
map[string]any` that it never used, and built `workflowcore.Options` without it.
`HasAppToggles` therefore fell back to `stages[].app_toggles`. That is harmless
*today* only because `options.json` states the app-toggle stages twice and the
two copies agree. Add stage 930 to `ui_rules.app_toggle_stages` without setting
`app_toggles: true` and the two guided surfaces silently diverge again — the
exact class the shared module exists to close.

`ui_rules` is now typed and passed to the core, and `actionOption` gained the
`supports_app_toggles` field the TUI already sent. `TestUIRulesReachTheCore`
pins the `ui_rules` path on its own, using a stage named only there; it fails
without the plumbing.

**The underlying duplication in `options.json` is unresolved** and is the next
thing to collapse. Both surfaces now read both copies identically, so the bug
cannot fire — but the two-copy shape remains.

### Dead code

`make_stub` in `tests/test_helper.bash` was used by zero tests. The plan wanted
the 312 heredoc stubs across 58 files folded into it; that did not happen and
the helper shipped unused. Removed. `setup_repo_root`, by contrast, is a clean
sweep — all 164 `.bats` files migrated, no stragglers.

`tools/platform-workflow-core/args.go` was not gofmt-clean. Formatted. Note the
gate does not run `gofmt -l`, so nothing would have reported it.

## The gate moved local (ADR 0011)

Chased down after the CI failures above, because the remote loop was the slow
part of finding them.

`make test-ci` now stamps `.run/ci-receipt.json` with a git tree hash of the
working-tree content it verified, built in a throwaway index so the real one is
untouched. `pre-push` runs `make lint` and then verifies that receipt instead of
running an 8-file subset. Match: passes instantly. Stale: refuses and names the
command.

Content, not `HEAD`, for a reason worth keeping: the fingerprint has to notice
uncommitted edits *and* survive the commit itself, because the normal sequence
is run the gate, commit, push. The first draft hashed `HEAD` plus
`git diff HEAD`, which invalidated itself at every commit and would have demanded
a second twelve-minute run for an already-verified tree.
`tests/ci-workflow.bats` pins both halves against a throwaway repo.

That raises what gates a push from **8 Bats files to 156**, without putting
twelve minutes inside the push — which cannot work, because git opens the SSH
connection before pre-push runs and the connection dies first.

GitHub CI dropped its `pull_request` trigger and keeps `push: branches: [main]`
plus `workflow_dispatch`. **A PR now shows no checks by default.** That is
deliberate; the receipt is the evidence. `push: main` is load-bearing and must
stay — dispatch-only CI is what let failures survive on `main` before.

Two CI cost fixes found on the way:

- `setup-go` was logging "Dependencies file is not found" and disabling the Go
  module and build caches entirely, because all 18 `go.mod` files are nested
  under `apps/` or `tools/` and it only looks in the workspace root.
  `cache-dependency-path: "**/go.mod"` fixes it.
- The apt step installed eight packages `ubuntu-latest` already ships, plus
  ripgrep, which it does not. `apt-get update` is where the six minutes went, so
  ripgrep is now pinned (`RIPGREP_VERSION=15.2.0`) and fetched from its GitHub
  release like shellcheck and kyverno. The apt branch remains as a fallback for
  a changed runner image and should not execute.

  The pin is registered in `.devcontainer/toolchain-sources.tsv`, so it is
  cooldown-governed by the same machinery as every other pin —
  `make update-versions --only tools` reports it as `15.2.0 / current`. It is
  also pinned for hosts in `mise.toml` (Ubuntu on slicer-mac, Arch on omarchy),
  with `check_mise_pin_drift` holding the two in step, and installed from the
  same pin in the devcontainer by `install-toolchain.sh` rather than by apt.
  One ripgrep version now covers devcontainer, both Linux hosts, and CI.
- The macOS job inherited the runner image's `aws/tap`, so Homebrew printed a
  long tap-trust notice on every invocation. Non-`homebrew/*` taps are dropped
  before installing; the three formulae are all core, so nothing else changes.

## A portable `timeout`, finally reachable

macOS has no GNU `timeout`, and neither does every minimal Arch or Ubuntu image.
A complete wrapper — `timeout`, then `gtimeout`, then a shell fallback returning
124 like coreutils — already existed in
`kubernetes/scripts/k3s-bootstrap-lib.sh`, reachable by exactly **one** script.
That is the 2026-08-17 review's candidate 7 verbatim: "1 retry wrapper,
unreachable".

It now lives in `scripts/lib/timeout.sh` as `run_with_timeout`.
`k3s_bootstrap_run_with_timeout` stays as a one-line alias so
`bootstrap-k3s-lima.sh` and its assertions did not have to move.
`tests/timeout-lib.bats` covers all three implementations, including the shell
fallback under a stripped `PATH` — the path that actually runs on a stock Mac.

This is why `check-version.bats` skips three tests on macOS rather than running
them, and why #204 had to strip a bare `timeout` out of the Kind 900 apply path.
Neither is fixed here; the shared helper is the prerequisite for fixing them, and
those call sites are the obvious next users.

## A FAIL that was really an unmet precondition

`.devcontainer/check-toolchain-surface.sh` reported

    FAIL could not resolve the devcontainer feature configuration

on any host where Docker was not running, because `devcontainer
read-configuration` shells out to `docker ps`. It did this on `main` too. The
script's own Feature Install Surface section already treated the identical
condition as a skip, so the two halves disagreed about whether it was a defect.

Docker-unavailable is now a `WARN` and a skip; a `read-configuration` failure on
a host that *does* have Docker still `FAIL`s, so the real signal survives.
A red line nobody can act on is how people learn to ignore red lines.
