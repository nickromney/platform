Adversarial review of PR #206 on branch `chore/20260818-cmd-review`, and the
fixes that review produced.

Supersedes the root `HANDOFF.md` written by the implementing agents, which is
deleted in this commit. Every claim in it was verified before deletion; two of

## State

`make test-ci` is 1130/1130 (exit 0), `make lint` is clean, and all three
Go modules build and test clean — including under `-race`, which the gate does
not run.

When this review started, CI on #206 was **red**: `lint-and-hermetic-bats`
failed with four test failures, while the branch's `HANDOFF.md` presented every

## What the review found

### Four regressions, now fixed

Three shared one root cause: **the `local-exec` heredoc extraction moved code
out of `.tf` files, and grep-contract tests still asserted it was there.** The
implementing agents hit this once and fixed it for
`kubernetes/kind/tests/gitops-refresh.bats`; two more files had the same
problem and were missed.

| Test | Asserted | Now lives in |
| --- | --- | --- |
| `kind/tests/platform-gateway-tls.bats:402` | `deadline=$((SECONDS + 180))` in `gateway-bootstrap.tf` | `scripts/wait-for-gateway-crds.sh`, parameterised as `CRD_WAIT_SECONDS` |
| `kind/tests/sso-oidc-health.bats:54,80` | the post-OIDC retry body in `sso.tf` | `scripts/check-cluster-health-after-oidc.sh` |

The fourth was independent: the new tests added to `tests/variant-contracts.bats`
used bare `python3`, which `tests/python-wrapper-policy.bats` forbids. Now
`uv run --isolated python`, matching `ci-workflow.bats` and
`review-environments.bats`.

Each repointed assertion now pins the *intent* rather than a literal that
parameterisation will delete — the failure mode `gitops-refresh.bats` already
documents in its own comments. Where the old test asserted the absence of
Terraform `$$` escaping, that intent is kept as a single `! grep -Fq '$$'`
against the plain script, where a surviving `$$` would mean a botched
extraction. Both `.tf` files also gained a test asserting they delegate to the
script and retain no heredoc.

### A pre-existing bug the extraction surfaced

`tools/platform-workflow-core/run.go` drained stdout and stderr from two
goroutines into one unsynchronised `bytes.Buffer`, and called the caller's
handler from both. `go test -race` reports a data race on
`bytes.Buffer.WriteString`.

**This was losing output.** With the mutex removed, the guard test sees 783–798
of 800 lines — the terminal TUI and the browser workflow UI have both been
silently dropping 0.5–2% of streamed lines, which on an `apply` means terraform
output vanishing from the operator's screen.

The code is inherited verbatim from the TUI on `main`, so #206 did not
introduce it — but extracting it into a shared module doubled its blast radius,
and the extraction was the moment to fix it. Fixed with a mutex around the
shared write.

The gate runs `go test ./...` with no `-race` anywhere, so a race-detector test
would guard nothing. `run_test.go` asserts the observable consequence instead:
every line arrives exactly once, on both streams. Verified to fail without the
mutex.

### Drift the refactor left open

`tools/platform-workflow-ui` parsed `options.json` into a `UIRules
map[string]any` that it never used, and built `workflowcore.Options` without it.
`HasAppToggles` therefore fell back to `stages[].app_toggles`. That is harmless
*today* only because `options.json` states the app-toggle stages twice and the
two copies agree. Add stage 930 to `ui_rules.app_toggle_stages` without setting
`app_toggles: true` and the two guided surfaces silently diverge again — the
exact class the shared module exists to close.

`ui_rules` is now typed and passed to the core, and `actionOption` gained the
`supports_app_toggles` field the TUI already sent. `TestUIRulesReachTheCore`
pins the `ui_rules` path on its own, using a stage named only there; it fails
without the plumbing.

**The underlying duplication in `options.json` is unresolved** and is the next
thing to collapse. Both surfaces now read both copies identically, so the bug
cannot fire — but the two-copy shape remains.

### Dead code

`make_stub` in `tests/test_helper.bash` was used by zero tests. The plan wanted
the 312 heredoc stubs across 58 files folded into it; that did not happen and
the helper shipped unused. Removed. `setup_repo_root`, by contrast, is a clean
sweep — all 164 `.bats` files migrated, no stragglers.

`tools/platform-workflow-core/args.go` was not gofmt-clean. Formatted. Note the
gate does not run `gofmt -l`, so nothing would have reported it.
